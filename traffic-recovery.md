# Workflow H: SEO Traffic Recovery

**Input**: domain, decline period, GSC exports (pages, queries, dates, devices, countries), GA4, crawl data, release/deploy log.
**Output**: root-cause investigation with confirmed vs suspected causes, recovery priorities, measurement plan.

Load: references/analytics-measurement.md (section 5), references/google-search-guidelines.md, references/technical-seo.md.

## Checklist

```
- [ ] 1. Phase 2 brief with 12-month window; list ranking updates and incidents overlapping the decline (Status Dashboard dates)
- [ ] 2. Confirm the drop is real: GSC vs GA4, tracking changes, property/filter changes
- [ ] 3. Shape: sudden vs gradual; sitewide vs section; branded vs non-branded; device; country
- [ ] 4. Technical: indexing report changes, crawl stats, robots/noindex/canonical/redirect/rendering changes around the date
- [ ] 5. Demand and seasonality: YoY, Trends
- [ ] 6. SERP changes for top lost queries: new features, AI Overviews, new competitors, intent shift
- [ ] 7. Algorithm overlap: compare page/query losses with update start-end windows; core vs spam patterns
- [ ] 8. Manual actions / security issues (if GSC access)
- [ ] 9. Content quality review of losing pages vs winners (helpful content self-assessment)
- [ ] 10. Label each cause: confirmed / likely / possible / ruled out, with evidence
- [ ] 11. Recovery plan: fix confirmed technical issues first (P0), then content/intent work; no "quick fix" claims for core updates
- [ ] 12. Measurement plan: annotations, weekly checks, expected timelines as ranges
- [ ] 13. QA + quality report
```

Never conclude "hit by the <name> update" from date overlap alone.
